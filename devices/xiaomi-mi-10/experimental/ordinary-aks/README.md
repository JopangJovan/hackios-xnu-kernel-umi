# 原厂 AppleKeyStore 框架的独立内核客户端

本实验接续 [原生保存事务](../native-keybag-transaction/README.md)。上一阶段发现，
共享缓存内的 AppleKeyStore 调用不会经过诊断程序的用户态符号拦截。本实验把隔离
边界放在内核客户端：原厂框架仍使用自己的 IOKit 连接，只有带明确测试 entitlement
的进程才得到独立袋。没有修改共享缓存，也没有把真实 `securityd` 改成测试服务。

## 隔离与失败处理

`stage.py` 只接受两个已知哈希的基线源文件，在一次性 XNU 构建树里加入实验。
构建树必须没有 `BUILD`：XNU 生成的 Makefile 含绝对源码路径，不能沿用复制来的
构建缓存。打包前还需确认目标内核包含本实验的 entitlement 和隔离入口标记。
客户端必须同时具备 `com.hakios.aks.ordinary-lab=true`、root 身份、类型 0 和
`umi_aks_lab=1` 启动参数。带测试 entitlement 却缺少其它条件时拒绝打开连接，
不回退到真实系统袋。其它客户端仍使用原来的路径。

探针先通过原厂 `aks_get_lock_state` 查询保留句柄，检查隔离回执；未取得回执
立即停止，不加载、认证或锁定任何袋。通过后才加载明确的公开合成袋，使用非零
句柄操作。另一个没有测试 entitlement 的父进程在前后读取真实系统袋的加密
序列化内容和状态，确认没有变化；即使子进程失败也执行这项核对。

普通类 6（WhenUnlocked）从当前解锁的主密钥派生；锁定擦除主密钥后拒绝使用。
类 7（AfterFirstUnlock）只保留独立派生的类别密钥，首次认证前不能使用，普通
重锁仍可用，卸载、进程退出或重启后清除。仅 C 类密钥不能派生 A 类或主密钥。
8–12 类明确返回不支持。本实验不提供 Secure Enclave、硬件绑定或防回滚保证。

封装沿用上一阶段 `UKW2` 与 RFC 3394 格式，旧测试条目不需要重写。
`HKwr` 明确返回需要迁移，损坏的新格式不回退到固定 XOR 旧算法。
新内核入口不执行旧条目迁移；上一阶段的显式合成夹具转换也不能等同于真实
钥匙串数据库迁移。

## 自动测试和构建

`core-test.c` 使用同一份内核封装核心，与上一阶段用户态实现逐字节对照。
覆盖 A/C 生命周期、锁定时不提供主密钥的 C 类读取、重启清除、大小边界、
逐字节损坏、类别替换及旧格式拒绝；使用 ASan/UBSan。

```sh
python3 devices/xiaomi-mi-10/experimental/ordinary-aks/build-test.py \
  --host-only --output /path/to/private/test-output
```

省略 `--host-only` 并传入 `--entitlements /path/to/probe-entitlements.plist`，
会构建原厂框架探针与父进程。脚本只给子进程添加隔离 entitlement，不启动
设备、不安装服务。`prepare-helper.py` 在新的 helper 目录中移除上一轮诊断
任务，加入这一轮自动探针，保留真实密码服务与 USB 配对配置。

本轮实机夹具明确读取上一轮 `/var/tmp/k75` 第 3 代公开测试袋，另存至
`/var/tmp/k78`；`create` 创建条目，`verify` 在重启后读取同一份文件。
不读取真实密码、不调用真实系统袋的解锁接口，也不写真实钥匙串数据库。
具体运行结果、镜像和日志摘要见 [results.json](results.json)；构建通过不等于实机通过。

`native-78` 创建和 `native-79` 跨原厂安卓重启读取均通过。两轮都由原厂框架直接
完成 A/C 生命周期、错误口令、旧测试条目兼容以及损坏/旧格式/不支持类别拒绝，
父进程核对真实袋序列化和状态未变。未请求任何人工密码操作。
两轮同步落盘返回 `errno=0`，随后均正常回原厂安卓；最终默认测试内核指针恢复
到既有验证版本。此目录代码尚未接入日常镜像。

`native-77` 是失败的构建对照：复制来的生成 Makefile 引用了旧源码，最终镜像
没有新隔离入口；只读预检拒绝后停止，未执行认证。后续干净构建纠正了来源，
`check-kernel.py` 也已确认拒绝旧镜像、接受包含新入口且原厂 USB 字节未变的候选。
本轮保留固件日志通道；它证明探针可观测，不等同于原生 USB 配对已重新回归。

## 尚未接入

这是原厂 AKS 函数到独立内核后端的测试，不是原厂 `SecItem` 数据库全链路。
后续仍需：独立 `securityd` 数据库 CRUD 与保护类检查、原生保存事务的持久
重试策略与丢失回执恢复、可信旧条目迁移，再集中做真实改密和 USB 配对回归。
在这些条件通过前，不迁移现有 iOS 数据，不加密整个 80 GiB，不修改安卓、
GPT 或启动分区。USB 源码和交接逻辑不属于本实验改动范围。

接独立 `SecItem` 时还需单独证明两个边界：测试客户端的 XPC 请求确实进入独立
服务，而不是共享缓存中默认的真实 `securityd`；数据库、WAL、SHM 与恢复文件都
限制在测试目录。当前客户端只加载非零测试句柄，尚不能让原厂服务使用其默认的
系统袋 0。下一步需要为测试服务增加明确隔离的句柄映射，先以只读回执证明服务和
袋身份，再允许 CRUD。不能只更改文件路径或拦截一个用户态符号就认定隔离成立。
