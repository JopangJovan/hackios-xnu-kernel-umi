# 原生保存事务与普通钥匙串接口的隔离验证

本目录在原有软件密钥袋基础上，测试 **iOS 16.5 原厂 keybagd 的保存顺序**，
以及 **AppleKeyStore.framework 的普通条目接口**。所有口令、条目和策略密钥
均为公开合成数据。它不替换正在使用的密码服务，不读取用户输入的密码，
不修改真实钥匙串数据库或 USB 配对记录，也不加密完整 `darwin` 分区。

后续已补充[保存结果不确定与回执丢失恢复](SAVE-RECOVERY.md)：确认当前提交后
再安装，精确重放不重复推进代次，不确定状态停止认证。该阶段使用单独的自动
探针与结果记录；下面原有 `results.json` 保留此前测试的源哈希和历史结果。

随后新增[持久失败计次与等待策略](RETRY-POLICY.md)，仅在显式启用的诊断副本中生效。
`native-83/84` 已通过计次/清零失败拒绝、服务退出恢复及跨安卓重启等待检查，
真实系统袋的内容与状态未变。详情和源哈希见
[retry-policy-results.json](retry-policy-results.json)；不等于真实锁屏服务已启用新策略。

后续 [原生 SecItem 组合验证](../isolated-securityd/TRANSACTIONS.md) 的 `native-94/95`
将这些事务与独立磁盘钥匙串相接：候选提交失败、提交后报错、服务退出丢失回执和
跨安卓重启后改密，均保持最初的 A/C 测试条目可读。新增 `fail-change-save` 标记
只在显式重试实验中的候选保存阶段注入失败，避免混同验证前计次/成功清零失败。
真实服务、认证通知、其它保护类和旧条目迁移仍未切换到这条诊断路径。

## 保存事务

`prepare-test.py` 只生成诊断副本，保留输入文件和原有服务：

- 校验本机已提取的诊断 keybagd 输入哈希；Apple 二进制不进 Git。
- 把数据目录改到明确的 `/var/tmp/kNN` 测试命名空间，服务、通知和队列名称
  改为 `com.hakio.mobile.keybagd`；添加强制加载的诊断库依赖。
- 诊断库先打开独立 AppleKeyStore 客户端，再通过 `umi_aks_lab=1` 的显式选择
  进入隔离袋。虚拟系统句柄 0 只映射到该客户端自己的测试袋，不传给真实系统袋。
  不允许访问 AppleEffaceableStorage。不开放未知 AKS 操作。
- 测试请求明确连接诊断 XPC 服务，使用原厂 `KBXPCProtocol`。口令通过匿名管道的
  `NSFileHandle` 传递，回调读取 `NSError`；不调用指向真实服务的改密入口。

原厂顺序是：创建候选 → 序列化 → 写 `.writing` 文件 → 原子替换 → 安装 → 完成。
适配层在原厂替换位置保存完整的原生属性列表，只解析并校验 `KeyBagKeys` 与候选袋
一致。安装操作必须在事务提交成功后才允许执行。失败时不把候选提前当作当前袋。

`journal.c` 使用带序号和 HMAC 的双副本记录，最后原子替换单独的提交记录。
每个文件及目录同步；加载只接受提交记录指向的当前代次，损坏一个副本可读另一个，
两个都损坏则拒绝，不扫描旧密码代次。提交成功后发生异常，应按已提交记录恢复，
不能把“函数返回错误”一概解释为“磁盘仍是旧版本”。重启会从提交记录重建原厂文件视图。

测试策略密钥是公开常量，仅验证流程与损坏检测，**不是生产认证根，也没有硬件防回滚**。
完全空的目录只有在测试控制器明确创建新夹具时才可初始化；删除全部记录再建空目录
不是本方案能够抵抗的攻击。进程退出注入不等同于实际断电、控制器缓存丢失或介质故障。

## 普通条目与旧格式

本地原厂 `securityd` 的映射证据见 [keyclass-reference.json](keyclass-reference.json)。

| 原生编号 | 类别 | 本轮独立适配行为 |
|---|---|---|
| 6 | WhenUnlocked | 当前认证后可用；锁定时清除该类密钥 |
| 7 | AfterFirstUnlock | 首次认证前拒绝；认证后普通重锁仍可用；退出/重启后清除 |
| 8–12 | 启动可用、设备专属、设密后设备专属等 | 明确不支持；不冒充设备硬件绑定 |

认证后仅保留类别密钥，立即清除临时主密钥。C 类保留的材料不能反推 A 类或主密钥。
改密保持袋身份与主密钥，因此已有条目仍可解密；试图换成另一份袋会清除状态并拒绝。

新封装为 `UKW2` 版本头、类别和 RFC 3394 AES-256 key wrap。类别参与密钥派生；
头部、保留位、长度与密文错误均检查，失败不写出部分明文。锁定返回权限错误，
旧格式返回需要迁移/尚未就绪，不把锁定或暂不可用误报成条目损坏。

现有 `HKwr` 是固定 XOR，**不是加密，也没有真实性校验**。普通解封装不会自动回退到
它；`umi_txn_import_fixture` 只在明确认证、显式调用时转换合成夹具。它证明格式转换，
不能证明任意旧条目的明文可信。尚未实现真实数据库逐条备份、转换、事务提交和回滚。
损坏的新格式绝不尝试当成旧 XOR 解码。

`ordinary-client.h` 按本机原厂框架反汇编核对过的参数布局，调用普通 AKS 的 IOKit
接口；`keychain-probe.c` 先用只读状态查询证明调用确实经过隔离适配层，确认后才
认证合成口令。它没有调用真实 `SecItem` 数据库，也没有启动第二个 securityd。

`native-74` 曾尝试直接调用共享缓存里的原厂框架：状态读取成功，但未经过诊断适配层，
只读保护检查立即终止了测试，未调用解锁/加锁/封装。**不能把该轮视为原厂框架接入成功**。
当时后续改用上述独立 IOKit 客户端。之后的 [ordinary-aks 实验](../ordinary-aks/README.md)
已让原厂共享缓存框架进入明确选择的内核隔离客户端；真实系统 `securityd`/`SecItem`
接入仍未完成，不能把两个阶段的验证范围混为一谈。

## 自动检查

宿主通过 ASan/UBSan 检查：

- 18 个返回错误点和相同位置的 18 个进程退出点，覆盖两个记录副本和提交指针；
  重新打开后必须是完整旧代或完整新代。
- 拒绝过期序号、缺失当前副本、错误提交记录及符号链接。
- A/C 生命周期、错误口令、改密后相同条目、另一份袋拒绝、大小边界、
  封装各字节损坏、显式旧夹具转换；错误时输出缓冲区不被部分覆盖。

手机 `native-73` 已通过原厂保存事务；`native-75` 进一步通过普通 IOKit 条目
创建、A/C 锁定生命周期、显式旧夹具转换，并核对真实系统密码袋内容/状态不变。
`native-76` 从同一份日志恢复并再次改密，原有两类条目在重启后、错误口令拒绝后
仍可使用新口令解开；真实系统密码袋再次核对一致。对应源码/镜像/日志摘要见
[results.json](results.json)。原始系统日志留在本机工作目录，
不提交含设备信息的日志、镜像、Apple 程序、真实密码袋或配对证书。

可在 macOS 构建宿主测试：

```sh
python3 devices/xiaomi-mi-10/experimental/native-keybag-transaction/build-test.py \
  --host-only --output /path/to/private/test-output
```

省略 `--host-only` 并提供 `--entitlements /path/to/probe-entitlements.plist` 可生成
诊断库、原生事务探针和普通钥匙串探针。该脚本不启动设备、不安装服务、不写分区。
手机测试仅使用临时 UEFI 启动；内核与 USB 交接代码保持现有验证版本。

## 接入真实系统前还缺什么

1. 保存异常恢复与持久失败策略已在原厂服务的诊断副本中统一；仍需补齐密码关闭策略、
   真实服务和界面错误提示，再做组合回归。独立诊断通过不等于真实密码服务已切换。
2. 独立 `SecItem` CRUD、A/C 磁盘持久化与改密组合验证已通过；仍需覆盖系统实际需要的
   其它保护类、首次解锁前依赖及设备专属语义，再决定真实旧条目如何可信迁移。
3. 完成后集中验证原生设密/改密、重锁、重启和 USB 配对/日志。现在不要求用户反复输密码。
4. 满足上述条件后再接正式数据卷；当前不改安卓、GPT 或启动分区，不加密 80 GiB。

软件密钥袋不具有苹果 Secure Enclave、硬件密码计数器或硬件密钥防导出保证。
